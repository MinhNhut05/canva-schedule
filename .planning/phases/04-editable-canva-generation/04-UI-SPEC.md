## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline icon spacing, badge-to-text spacing, dense status rows |
| sm | 8px | Button icon gap, stacked helper text gap, compact action spacing |
| md | 16px | Default card padding rhythm, form/control spacing, result-card internals |
| lg | 24px | Section padding, panel padding, vertical spacing between major review subsections |
| xl | 32px | Gap between review content and Canva generation section |
| 2xl | 48px | Major page section break before persisted Canva results |
| 3xl | 64px | Reserved for full-page top/bottom breathing room only |

Exceptions: 44px minimum hit area for icon-only or compact utility actions, including copy/open controls if they are rendered as icon buttons.

Phase 04 spacing rules:
- Keep the existing review page as the primary layout; append Canva generation UI below reviewed itinerary/menu content.
- Use 24px vertical gap between the editor grid, template confirmation panel, generation status panel, and result cards.
- Use 16px internal padding for template confirmation and result cards.
- Use 8px gap between adjacent secondary actions such as `Mở trong Canva` and `Sao chép link`.
- Keep the sticky bottom action bar at 16px vertical padding to match the current review action pattern.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Typography rules:
- Use only these four sizes in Phase 04. Do not introduce 12px, 18px, 24px, or 32px text.
- Body copy, helper text, alert descriptions, and empty-state body text use 16px / 400.
- Button labels, field labels, status labels, and card metadata labels use 14px / 600.
- Section titles such as `Xác nhận mẫu Canva` and `Kết quả Canva` use 20px / 600.
- Large page-level headings can use 28px / 600 only in the review header, not inside cards.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #F8FAFC | Page background, empty-state surface, low-emphasis section background |
| Secondary (30%) | #FFFFFF | Cards, sidebar, sticky action bar, template confirmation panel |
| Accent (10%) | #3B82F6 | Primary Canva actions, selected template state, focus ring, progress spinner |
| Destructive | #EF4444 | Failed generation state, retry-needed status, destructive/severe error messaging only |

Accent reserved for: `Tạo Canva`, `Tạo lại`, `Thử lại` when promoted as the primary action, active navigation state, selected template confirmation border/icon, generation spinner/progress treatment, and keyboard focus ring. Never use accent on every clickable element.

Color rules:
- Keep cards neutral by default; do not turn all result cards blue.
- Success is communicated by content, badge text, and optional subtle green alert styling already present in the codebase; do not add a new global success token in this phase.
- Use destructive red only when a Canva artifact failed, the request timed out, the template is invalid, or rate limiting blocks retry.
- Copy-link feedback should use toast feedback, not permanent accent backgrounds on result cards.

## Phase-Specific Interaction Contract

### 1. Entry and gating
- Canva generation UI appears only after the upload is in `APPROVED` review state.
- The approval action and generation action are separate. Do not keep the combined `Xác nhận & Tạo Canva` label in the final Phase 04 UI.
- Before approval, the sticky action bar shows only the approval CTA.
- After approval, the sticky action bar switches to the Canva generation flow.

### 2. Template confirmation panel
- Template selection is automatic from `tourDuration`; users confirm, not manually browse a dropdown.
- Show one confirmation panel titled `Xác nhận mẫu Canva` directly below the reviewed content.
- The panel must list exactly two templates for the active duration: `Lịch trình` and `Thực đơn`.
- For 1-day tours, show the resolved pair as `Tour 1 ngày — Lịch trình` and `Tour 1 ngày — Thực đơn`.
- For 2-day tours, show the resolved pair as `Tour 2 ngày — Lịch trình` and `Tour 2 ngày — Thực đơn`.
- Use a selected-state treatment with accent border/ring, but keep the panel background white.
- No manual template dropdown is allowed in v1.

### 3. Generation flow
- Clicking `Tạo Canva` starts both `Itinerary` and `Menu` generations in parallel.
- Do not redirect to another page while generating.
- Show an inline generation panel on `/review/[id]` with spinner, current step text, and helper copy: `Quá trình này thường mất 10–30 giây.`
- Disable duplicate submissions while generation is active.
- The spinner and progress treatment use accent blue only; do not add a multi-color progress meter in this phase.

### 4. Result presentation
- Render results directly below the generation panel on the review page.
- Show two separate result cards: `Lịch trình` and `Thực đơn`.
- Desktop: 2-column grid when space allows.
- Mobile: stack cards in one column.
- Each card contains, in this order:
  1. card title,
  2. status badge,
  3. optional thumbnail preview,
  4. helper/meta text,
  5. action row.
- The action row order is fixed: primary `Mở trong Canva`, secondary `Sao chép link`, tertiary `Thử lại` only when that specific artifact failed.
- Thumbnail is optional. Missing thumbnail must not block the card or move actions off-screen.

### 5. Partial success and retry
- `Lịch trình` and `Thực đơn` are independent artifacts with independent statuses.
- If one succeeds and one fails, keep the successful card fully actionable and show retry only on the failed card.
- `Tạo lại` is allowed after any completed attempt and regenerates a fresh pair from the already approved content.
- `Thử lại` on a failed card retries only that failed artifact, not both.

### 6. Persistence and revisit behavior
- Generated Canva links persist on `/review/[id]` and reappear when the user revisits the page.
- The durable reference is `designId`; the UI must not assume `edit_url` is permanently valid.
- When returning to the page later, cards should rehydrate from persisted generation state and freshly resolved URLs.
- The UI must never imply that thumbnails are permanent assets.

### 7. Rate limiting and cooldown
- On rate limiting, show an inline destructive alert above the result cards.
- Disable `Tạo Canva` and `Thử lại` for the cooldown period.
- Show a visible countdown or remaining-wait indicator in the same panel.
- Keep already generated successful cards usable during cooldown.

## State Contracts

| State | Visual treatment | Required copy | Available actions |
|------|------------------|---------------|-------------------|
| Approved, not generated | White confirmation panel + neutral helper text | `Nội dung đã được duyệt. Hãy xác nhận mẫu Canva rồi bắt đầu tạo liên kết.` | `Tạo Canva` |
| Generating | Inline panel with accent spinner and disabled CTA | `Đang tạo Canva...` + `Quá trình này thường mất 10–30 giây.` | none |
| Success | Neutral result card + status badge + optional thumbnail | `Liên kết Canva đã sẵn sàng.` | `Mở trong Canva`, `Sao chép link`, `Tạo lại` |
| Partial success | One success card and one failed card shown together | Failed card uses error copy; success card remains actionable | Success card: `Mở trong Canva`, `Sao chép link`; failed card: `Thử lại` |

| Rate limited | Destructive alert + disabled CTA + countdown | `Canva đang bận, vui lòng thử lại sau {X phút}.` | none until cooldown ends |
| No result yet | Empty-state panel below confirmation area | `Chưa có liên kết Canva` + empty-state body | `Tạo Canva` |

## Layout Contract

- Keep the current review page header and editor grid unchanged.
- The Canva section order is fixed:
  1. approval success alert,
  2. template confirmation panel,
  3. generation status panel,
  4. result cards.
- The sticky footer remains the global action surface; do not place another competing full-width CTA inside each card.
- Result cards may contain their own scoped retry action only when needed.
- Sidebar and existing page chrome remain unchanged in Phase 04.

---

## Implementation Guardrail

- UI copy and flows follow the locked Phase 04 decisions: approve on the review page, confirm the resolved template pair, generate in place, and show two editable-result cards on the same page.
- Implementation must keep a server-side Canva adapter boundary because Phase 04 research found a capability mismatch between the desired regular-design Canva Pro workflow and the officially documented Brand Template Autofill path.
- The UI must therefore avoid promising in-app Canva editing, permanent URLs, or guaranteed thumbnails.
