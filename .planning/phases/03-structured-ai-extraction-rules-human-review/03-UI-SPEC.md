- Default text color: `#0F172A` for headings, body text, labels, and field content.

## Phase-Specific Layout & Interaction Contract

### Page structure
- Route: `/review/[id]` in the protected `(app)` area.
- Desktop layout (`>= 1024px`): two equal columns with a `32px` gap.
  - Left column: itinerary editor.
  - Right column: menu editor.
- Tablet/mobile (`< 1024px`): stack vertically in this order: itinerary first, menu second.
- Keep a persistent top page header with:
  - page title,
  - upload file name,
  - extracted metadata badges for duration, client type, and review status,
  - secondary action `Trích xuất lại`.
- Keep the primary approval action in a sticky bottom action bar on long pages so the user can confirm without scrolling back to the top.

### Visual hierarchy and focal points
- Primary visual anchor: the editable 2-column content area containing the itinerary editor and menu editor.
- Highest scan priority within that content area: flagged or warning fields that require review.
- Secondary focal point: the sticky bottom approval bar containing `Xác nhận & Tạo Canva`.
- The top page header provides context only and must not visually compete with editable content.

### Visual style adaptation from Canva sample
- Mirror the Canva sample’s clean white content area and dark blue framing, but avoid decorative image-heavy elements inside the review workspace.
- Use dark blue only as structural emphasis: section headers, primary button, selected states, and divider accents.
- Use white cards with clear border separation rather than fully filled dark-blue panels, because this screen is for editing dense text.

### Section structure
- One-day tours must render two itinerary sections labeled exactly `Buổi sáng` and `Buổi chiều`.
- Two-day tours must render two itinerary sections labeled exactly `Ngày 1` and `Ngày 2`.
- Menu sections must mirror the selected duration structure and remain visually separate from itinerary content.
- Each section uses a clear heading bar, body content area, and per-field spacing aligned to the scale above.

### Inline edit behavior
- Default state: extracted content is readable text, not an always-open form.
- Interaction: a single click on a field enters inline edit mode directly in place.
- Edit mode must visually switch with:
  - a 2px accent border,
  - white background retained,
  - visible save/cancel controls or an equivalent explicit commit/cancel pattern.
- Single-line fields use `input`; multi-line itinerary/menu content uses a multiline text field or textarea-like control.
- `Escape` cancels the current inline edit without saving.
- `Enter` may save only for single-line fields; multi-line fields must not save on bare Enter.
- Saving must show an immediate pending state on the edited field and preserve surrounding scroll position.

### Flagged and uncertain fields
- Any field marked `needsReview` or included in `reviewFlags[]` must display:
  - 2px warning border (`#F59E0B`),
  - warning icon,
  - short helper text explaining what needs confirmation,
  - higher visual priority than non-flagged fields.
- Flagged state must remain visible even after the user opens edit mode until the server confirms the issue is resolved.
- Do not hide uncertainty behind a generic badge alone; the field container itself must carry the warning styling.

### Buttons and actions
- Primary CTA label: `Xác nhận & Tạo Canva`.
- Primary CTA uses accent blue fill with white text and is the only fully filled high-emphasis button on the page.
- Secondary action `Trích xuất lại` uses outline or secondary styling when the draft is pristine.
- If the draft contains user edits, clicking `Trích xuất lại` must require confirmation before overwrite.
- Confirmation copy for overwrite must match the copywriting contract exactly.

### Feedback states
- AI-generated content that is valid but incomplete should remain editable and reviewable; do not block the page with a full error state.
- Inline-save success should use subtle confirmation (field-level success text or toast), not a disruptive modal.
- Extraction failure should render a page-level alert near the top and keep the recovery action visible.

### Accessibility and readability
- All interactive controls must preserve visible focus rings.
- Minimum contrast target: text and controls must meet accessible contrast on white and pale warning backgrounds.
- Long Vietnamese copy must wrap naturally, except school names and other canonical names that must stay logically intact.
- Avoid center-aligning dense itinerary or menu text; use left alignment for all editable body content.
