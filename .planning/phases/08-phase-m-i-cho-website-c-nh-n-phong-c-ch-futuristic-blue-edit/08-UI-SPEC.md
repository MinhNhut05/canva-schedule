## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Hairline icon gaps, micro-label spacing, decorative offset |
| sm | 8px | Tight inline spacing, icon-to-label gap, compact nav internals |
| md | 16px | Default control padding, button gap, paragraph-to-label rhythm |
| lg | 24px | Card padding, nav item spacing, grouped component separation |
| xl | 32px | Section-level component spacing, hero content stack gap |
| 2xl | 48px | Major visual breaks inside hero or premium feature clusters |
| 3xl | 64px | Large top/bottom breathing room for anchor sections only |

Exceptions:
- Interactive controls must keep a minimum 44px touch target even when internal spacing appears visually smaller.
- Thin technical tags may use `4px 8px` internal padding to preserve the intended micro-label feel.
- Hero accent ornaments may use 4px positional offsets for visual polish only; these are decorative offsets, not layout spacing tokens.

Spacing rules:
- Default vertical rhythm between a component title and supporting text: 8px.
- Default vertical rhythm between a component body block and actions: 16px.
- Primary cards use 24px internal padding on desktop and 16px on compact layouts.
- Nav items and buttons must feel compact-premium, not oversized SaaS blocks.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 700 | 1.4 |
| Heading | 24px | 700 | 1.2 |
| Display | 56px | 700 | 1.05 |

Typography rules:
- Headline font is `Space Grotesk`; body, labels, inputs, and long-form UI text use `Inter`.
- Headlines use mixed case only. Full uppercase is prohibited for primary display/headline usage.
- Weight contract is limited to `400` and `700` across the entire phase.
- Long body copy must stay on stable, high-contrast surfaces and always use `Inter 16px / 1.5 / 400`.
- Labels, nav items, buttons, and technical microcopy use `14px / 700 / 1.4` unless a component-specific rule below overrides line-height.

Component-specific typography:

| Component | Element | Font | Size | Weight | Line Height |
|-----------|---------|------|------|--------|-------------|
| Hero | Eyebrow / technical kicker | Inter | 14px | 700 | 1.3 |
| Hero | Main headline | Space Grotesk | 56px | 700 | 1.05 |
| Hero | Supporting paragraph | Inter | 16px | 400 | 1.6 |
| Navigation | Brand / key nav item | Inter | 14px | 700 | 1.2 |
| Button | Label | Inter | 14px | 700 | 1 |
| Card | Title | Space Grotesk | 24px | 700 | 1.2 |
| Card | Body text | Inter | 16px | 400 | 1.5 |
| Tag | Technical label | Inter | 14px | 700 | 1.2 |
| Input | Label | Inter | 14px | 700 | 1.3 |
| Input | Field text | Inter | 16px | 400 | 1.4 |

Additional rules:
- Technical labels and tags may use slight tracking (`0.04em`) to feel editorial-tech, but do not simulate loud sci-fi typography.
- White text is reserved primarily for hero and dark-surface components.
- Dark text dominates on light body surfaces.

Accent reserved for:
- Primary button fills
- Active navigation indicator
- Keyboard focus ring
- Link hover underline/fade accent
- Selected/active card outline when selection is needed
- Hero glow support layer
- Hover glow on premium interactive elements

Accent must not be used for:
- Long-form paragraph text
- Large blocks of card background fill
- Multiple adjacent components at once in the same cluster
- Decorative noise without interaction or hierarchy purpose

Surface and effect rules:
- Hero gradient is locked to a navy-to-electric-blue direction close to `linear-gradient(135deg, #08101E 0%, #0B2FAE 48%, #1464F4 100%)`.
- Light content sections use cool white or blue-tinted white only; warm cream or beige whites are prohibited.
- Dark glass surface target: `rgba(8,16,30,0.72)`.
- Light glass surface target: `rgba(255,255,255,0.72)` and only where contrast remains safe.
- Dark card shadow: `0 12px 30px rgba(0,0,0,0.22)`.
- Light elevation shadow: `0 10px 30px rgba(11,47,174,0.08)`.
- Glow shadow: `0 0 40px rgba(124,184,255,0.18)`.
- Borders must remain cool, subtle, and blue-tinted; hard neutral gray strokes are out of contract.

60/30/10 application rule:
- Roughly 60% of the system should feel grounded in light/cool-white readable surfaces.
- Roughly 30% should be dark navy/deep-blue premium framing, concentrated in hero, nav overlay, and selective dark cards.
- Roughly 10% should be electric-blue accent emphasis, used surgically.

## Component-Specific Visual Contract

### 1. Hero
- The hero is the highest-energy visual zone in the entire system.
- Base treatment: dark navy foundation with the locked navy-to-electric-blue gradient.
- Allowed overlays: faint grid, almost invisible grain, restrained radial glow, sparse geometric micro-ornaments.
- Glow must support hierarchy, not obscure text.
- Headline uses `Space Grotesk 56px / 700 / 1.05`, mixed case.
- Supporting paragraph must sit on a clearly readable dark area, never directly over a bright glow bloom.
- Hero body text width should remain readability-first when implemented later; do not create poster-like ultra-wide paragraphs.

### 2. Navigation
- Over hero: semi-transparent dark overlay with blur kept restrained.
- Over light sections: calmer light adaptation with cool border or subtle bottom edge separation.
- Active state may use a subtle underline fade, soft glow, or precise accent indicator.
- Nav must feel premium and exact, not loud or oversized.
- Avoid large filled pills for default nav items.
- Brand mark/text should feel crisp and technical, not playful.

### 3. Buttons
- Radius is locked to `16px`.
- Primary button: electric blue fill, white text, soft glow-on-hover, optional `-2px` translate max.
- Secondary button: transparent or lightly glassed/light-outline surface, cool border, no heavy fill.
- Tertiary/text button: minimal surface treatment, color shift or underline/fade only.
- Button motion must stay within `180-240ms` and never feel springy or bouncy.
- Primary CTA is the only button class allowed to carry the strongest accent fill in a local cluster.

### 4. Cards
- Card radius is locked to `20px`.
- Preferred identity: dark-tinted or translucent surface with soft shadow and subtle cool border.
- Light-surface card variant is allowed in body sections for readability-heavy content, but must preserve the same cool premium language.
- Optional top-edge highlight is allowed as a restrained detail only.
- Cards are supportive structure, not the main visual spectacle.
- Cards must never rely on loud blue fills to feel premium.

### 5. Tags / Badges
- Fully rounded pill shape is allowed; styling must remain thin and technical.
- Compact padding, light border, minimal fill, subtle contrast.
- Casing should feel editorial-tech; avoid chunky badge styling.
- Tags must remain visually lighter than buttons and cards.
- Use them for metadata or category markers only, not as dominant calls to action.

### 6. Inputs
- Inputs are intentionally the quietest component in this phase.
- Base surface: light or lightly tinted, high readability, dark text.
- Focus state: subtle blue ring and cool border enhancement only.
- Heavy glow, dark-glass styling, or decorative overlays are prohibited on inputs.
- Placeholder and helper text must stay readable and understated.
- Inputs must not visually compete with hero, nav, buttons, or cards.

## Interaction & State Contract

### Shared motion rules
- Hover motion is subtle only.
- Max translate on hover: `-2px`.
- Scale changes, if any, must remain minimal (`1.01` feel, not visibly enlarging).
- Transition duration target: `180-240ms`.
- Use ease-out or similarly calm timing; avoid elastic or playful motion.

### Hover and focus behavior
- Primary button hover: brighter surface impression plus soft glow, no aggressive bloom.
- Secondary button hover: slightly stronger border contrast and gentle background tint.
- Card hover: optional tiny lift or border-brightening; do not convert the whole card into an accent block.
- Link hover: underline fade, glow-thread, or subtle color shift depending on surface.
- Focus must be visible and use accent blue with accessible contrast on both dark and light surfaces.

### Texture and overlay usage
- Grain intensity must remain almost invisible.
- Grid overlays must stay faint and mostly confined to hero or accent framing areas.
- Decorative crosses, lines, and technical marks must be sparse and geometric.
- Never stack grain + strong grid + strong glow + heavy shadow in the same local component.

### Readability guardrails
- White text lives primarily on dark surfaces.
- Dark text dominates on light surfaces.
- Paragraphs must never be placed directly over bright glow zones.
- Body sections must step down in visual intensity from the hero.
- Inputs and long-form readable blocks must avoid glass-dark treatment if it reduces clarity.

### State-specific rules

| State | Contract |
|------|----------|
| Default | Premium, calm, high-contrast; effects are visible but restrained |
| Hover | Slight glow shift, fade, border lift, or micro-translate only |
| Active / selected | Accent indicator becomes clearer, but never floods the component |
| Focus-visible | Blue ring or edge highlight with accessible contrast |
| Disabled | Reduce glow and contrast; keep text readable; never simulate interactivity |
| Error / destructive | Use destructive color only for real destructive or failure states; do not blend with accent-blue semantics |
| Empty | Use light, low-noise surface and neutral explanatory copy; avoid decorative drama |
