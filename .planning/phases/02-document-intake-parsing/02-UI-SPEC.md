## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge spacing, inline helper text offsets |
| sm | 8px | Label-to-field spacing, compact metadata rows |
| md | 16px | Default card padding units, form control gaps, body content spacing |
| lg | 24px | Section padding, card interior spacing, sidebar item grouping |
| xl | 32px | Layout gaps between sidebar and page content, result sections |
| 2xl | 48px | Major section breaks inside upload page |
| 3xl | 64px | Top-level page breathing room on desktop |

Exceptions: minimum interactive hit area 44px for clickable nav items, file picker trigger, destructive-secondary buttons, and warning banner actions.

Phase-specific application:
- Upload page outer container uses `3xl` vertical rhythm on desktop and `xl` on tablet.
- Main upload card uses `xl` internal padding.
- Drag/drop zone uses `lg` padding on mobile and `2xl` padding on desktop.
- File preview rows use `md` vertical gaps.
- Extraction result header and raw-text panel are separated by `xl`.
- Sidebar nav groups use `lg` between sections and `sm` between items.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Typography rules:
- Use exactly two weights in this phase: 400 and 600.
- Body copy, helper text, metadata, warning descriptions, and raw-text content use 16px / 400.
- Field labels, section labels, status chips, and nav item labels use 14px / 600.
- Card headings and section headings use 20px / 600.
- The page title `Tải lên và trích xuất tài liệu` uses 28px / 600.
- Do not introduce 12px microcopy for this phase; use 14px minimum for readability.

Source: defaults applied because upstream artifacts did not lock specific type tokens.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #F8FAFC | App background, page canvas, raw text reading surface |
| Secondary (30%) | #FFFFFF | Cards, sidebar surface, file preview surface, result containers |
| Accent (10%) | #2563EB | Primary CTA, active nav item, drag/drop active border, focus-visible ring, progress/loading emphasis |

## Phase 2 Component Contract

### 1. App Sidebar / Navigation
Use shadcn/ui `Sidebar` pattern if initialized; otherwise implement an equivalent layout that matches these contracts.

Required items:
- Brand area: `SileTravel`
- Primary nav items: `Dashboard`, `Tải tài liệu`
- Reserved disabled or muted placeholders are allowed for future items: `Lịch sử`, `Cài đặt`
- User meta area: full name + username
- Secondary action: `Đăng xuất`

Interaction rules:
- Sidebar is persistent on desktop, collapsible sheet/drawer on smaller screens.
- Active item uses accent background tint and accent text.
- Hover state uses neutral surface tint, not full accent fill.
- Keyboard focus must show a visible 2px accent ring.
- Current page title must also appear in page content area; sidebar state alone is not sufficient.

Layout rules:
- Sidebar width: 240px desktop.
- Content area max width: 960px for Phase 2 upload workflow.
- Sidebar and content separated by `xl` gap on desktop.

### 2. Upload Page Shell
Page structure order:
1. Page title
2. One-sentence helper text
3. Upload card
4. Extraction result area (only after processing)

Required title and helper copy:
- Title: `Tải lên và trích xuất tài liệu`
- Helper: `Tải file PDF hoặc DOCX để lấy văn bản thô trước khi chuyển sang bước AI.`

Interaction rules:
- Keep the flow linear: chọn file -> xem thông tin -> bấm `Xử lý` -> xem kết quả.
- Do not auto-submit on drop or file selection.
- The page must never show AI review or Canva generation controls in Phase 2.

### 3. Drag & Drop Upload Zone
Recommended shadcn/ui building blocks:
- `Card`
- `Button`
- `Input` for hidden file input
- `Separator` optional for helper grouping

Visual rules:
- Dashed border 2px neutral by default.
- Background remains secondary surface; do not use dark fills.
- Centered upload icon above headline.
- Zone minimum height 220px desktop, 180px mobile.

States:
- Default: neutral border + helper copy.
- Drag active: accent border + accent-tinted background.
- Selected: success border tint plus file summary replaces generic helper.
- Disabled while processing: reduced opacity, not-allowed cursor, all file actions disabled.
- Error: error border + inline error text under zone.

Required copy inside zone:
- Headline: `Kéo và thả file vào đây`
- Support line: `Hoặc chọn file từ máy tính của bạn`
- Format hint: `Hỗ trợ: PDF, DOCX · Tối đa 10MB · Mỗi lần chỉ 1 file`
- Trigger button: `Chọn file`

Behavior rules:
- Accept only one file.
- Reject unsupported file before upload with Vietnamese inline message.
- Reject over-10MB file before upload with Vietnamese inline message.
- Keep dropped file name visible immediately after selection.

### 4. File Preview Panel
Use `Card` or inset panel directly below the upload zone after a valid file is selected.

Required fields:
- `Tên file`
- `Kích thước`
- `Loại file`
- `Trạng thái`

Status values before extraction:
- `Sẵn sàng xử lý`
- `Đang xử lý`
- `Xử lý thất bại`
- `Đã trích xuất`
- `Đã trích xuất kèm cảnh báo`

Actions:
- Primary button: `Xử lý`
- Secondary text/button action before processing: `Chọn file khác`

Interaction rules:
- `Xử lý` remains disabled until there is exactly one valid file.
- On processing, button label changes to `Đang xử lý...`.
- Secondary replace-file action is hidden or disabled during processing.
- Preview panel must remain visible while processing so the user retains context.

### 5. Extraction Result Display
Use stacked cards/panels under the upload card.

Required sub-sections:
1. Result summary header
2. Advisory warning banner when quality is not good
3. Raw text preview area
4. Next-step note for Phase 3 handoff

Result summary content:
- Heading: `Kết quả trích xuất`
- Metadata rows: file name, loại file, thời gian xử lý, chất lượng
- Quality badge values: `Tốt`, `Cần kiểm tra`, `Thấp`

Raw text preview rules:
- Show plain text only; never render document HTML.
- Use monospaced or regular body font in a scrollable reading panel with preserved line breaks.
- Minimum visible height 320px desktop, 240px mobile.
- Panel background stays high-contrast white on dominant page background.
- Allow text selection and copy.
- If text is very long, clamp panel height with internal scroll instead of expanding infinitely.

Next-step note copy:
- `Bạn có thể kiểm tra nhanh nội dung bên dưới trước khi chuyển sang bước trích xuất AI ở Phase 3.`

### 6. Quality Warning Banner
Use shadcn/ui `Alert` if available.

When shown:
- quality level `Cần kiểm tra`
- quality level `Thấp`

Visual rules:
- Yellow warning surface (`#FEF3C7`) with brown text/icon (`#92400E`).
- Left-aligned warning icon.
- Banner spans full result card width.
- Never use destructive red for advisory extraction quality warnings.

Required copy for poor quality state:
- Title: `Chất lượng trích xuất thấp`
- Body: `Nội dung lấy ra có thể không chính xác. Bạn có thể tiếp tục kiểm tra hoặc tải file khác để thử lại.`

Required copy for warning state:
- Title: `Nội dung cần kiểm tra lại`
- Body: `Hệ thống đã trích xuất được văn bản nhưng có dấu hiệu chất lượng chưa ổn. Hãy xem kỹ trước khi dùng cho bước tiếp theo.`

Actions inside or below banner:
- `Tiếp tục kiểm tra`
- `Tải file khác`

Interaction rules:
- Banner is advisory only; it must not block access to raw text.
- If the user chooses `Tải file khác`, reset the selection and hide the current result view.

### 7. Error State Contract
Error presentation must appear inline in context first; toast is supplementary only.

Required error surfaces:
- Inline field/zone validation errors before upload
- Inline result card error for server/parser failure
- Optional Sonner toast echo for transient visibility

Approved Vietnamese error copy:
- Unsupported format: `Định dạng file không được hỗ trợ. Vui lòng chọn file PDF hoặc DOCX.`
- Too large: `File vượt quá 10MB. Vui lòng chọn file nhỏ hơn.`
- Missing file: `Vui lòng chọn một file trước khi xử lý.`
- Extraction failed: `Không thể trích xuất nội dung từ file này. Vui lòng thử lại hoặc dùng file nguồn rõ hơn.`
- Session/auth issue: `Phiên đăng nhập đã hết hạn. Vui lòng đăng nhập lại để tiếp tục.`
- Generic upload failure: `Có lỗi xảy ra khi xử lý file. Vui lòng thử lại sau.`

Interaction rules:
- On server-side failure, preserve selected file metadata so the user understands what failed.
- Provide a visible retry path via `Chọn file khác` or `Thử lại` only when retry is technically safe.
- Do not clear the page into a blank state immediately after an error.

### 8. Loading / Processing State
Phase 2 includes one processing step only: extraction.

Rules:
- Show processing state on the primary button and result summary area.
- Recommended status row copy: `Đang phân tích file và trích xuất văn bản...`
- Show indeterminate loader; do not imply exact percentage because Phase 2 does not have reliable sub-step timing.
- Disable upload replacement while the request is active.
- Keep layout stable; no large shifting or collapsing.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Xử lý tài liệu |
| Empty state heading | Chưa có tài liệu nào được chọn |
| Empty state body | Hãy kéo thả file PDF/DOCX vào vùng tải lên hoặc bấm `Chọn file` để bắt đầu. |
| Error state | Có lỗi xảy ra khi xử lý tài liệu. Vui lòng kiểm tra lại định dạng, dung lượng hoặc thử file nguồn khác. |
| Destructive confirmation | Thay file đã chọn: `Bạn có chắc muốn bỏ file hiện tại để chọn file khác không?` |

Additional locked copy for this phase:
- Upload helper: `Mỗi lần chỉ xử lý 1 file để dễ kiểm tra kết quả trích xuất.`
- Raw text empty placeholder: `Văn bản trích xuất sẽ hiển thị ở đây sau khi xử lý.`
- Success summary: `Đã trích xuất văn bản thành công.`
- Success with warning summary: `Đã trích xuất văn bản nhưng cần kiểm tra kỹ trước khi dùng tiếp.`
- Sidebar upload label: `Tải tài liệu`

Copy rules:
- All visible UI text must be Vietnamese.
- Use direct internal-tool language; avoid marketing tone.
- Use sentence case, not ALL CAPS.
- Prefer short action-first labels: `Chọn file`, `Xử lý`, `Tải file khác`, `Tiếp tục kiểm tra`.
- Do not use English labels in buttons, statuses, or alerts.
