## Phase-Specific Interaction Contract

### 1. History page
- Route is `/history`.
- Layout order: page header, single table container, bottom pagination. Do not add filter bars, search, tabs, or analytics widgets in v1.
- Table columns, in this order: `Tên file`, `Ngày tạo`, `Trạng thái`, `Loại tour`, `Liên kết Canva`.
- Table rows are ordered newest first.
- One row represents one upload or generation job. Never split itinerary and menu into separate rows.
- Entire row is clickable and opens `/review/[id]`.
- Hover state uses muted background only. Selected or keyboard-focused row uses accent-tinted background plus visible focus ring.
- Row click interaction must still expose an actual keyboard-focusable target. Enter and Space must trigger reopen behavior; pointer-only rows are not acceptable.
- Status rule for row-level `Trạng thái`:
  - `Thành công` when at least one Canva artifact succeeded.
  - `Lỗi` only when no Canva artifact succeeded.
- `Liên kết Canva` is separate from row-level status and must use text-first labels:
  - `2 liên kết` when both artifacts succeeded.
  - `1/2 liên kết` when partial success exists.
  - `Chưa có liên kết` when no artifact succeeded.
- Empty state uses a centered card-like panel with display heading, body copy, and one primary CTA button labeled `Tải tài liệu` linking to `/upload`.
- Pagination sits below the table. Desktop alignment: right. Mobile alignment: centered. Use numbered buttons only; no infinite scroll.
- Loading state uses skeleton rows that match the five-column table structure.
- No bulk actions, no multi-select, and no inline edit on the history table.

### 2. Sidebar and access contract
- Enable the existing `Lịch sử` item in sidebar navigation and route it to `/history`.
- Add an admin-only section labeled `Quản lý` below the primary navigation group and above the account footer block.
- `Quản lý` contains exactly two sub-items in this phase:
  - `Quy tắc` -> `/admin/rules`
  - `Mẫu Canva` -> `/admin/templates`
- Member users must not see the `Quản lý` section at all.
- Non-admin users hitting `/admin/rules` or `/admin/templates` directly must receive a server-protected 403 state inside the app shell, not a silent client-only hide.
- 403 state copy:
  - Heading: `Bạn không có quyền truy cập`
  - Body: `Trang này chỉ dành cho quản trị viên. Hãy quay về bảng điều khiển hoặc liên hệ người quản lý nếu bạn cần hỗ trợ.`
  - CTA: `Về bảng điều khiển`

### 3. Rule management contract
- Route is `/admin/rules`.
- Primary surface is a table inside a card container.
- Table columns, in this order: `Rule ID`, `Tên quy tắc`, `Danh mục`, `Trạng thái`.
- Clicking anywhere on a row except the inline toggle opens a right-side edit sheet.
- Desktop edit pattern: right-side sheet. Mobile edit pattern: full-width sheet.
- The row-level active toggle is directly operable without opening the sheet. Toggle interaction must not accidentally trigger row open.
- Seeded rules `RULE-01` through `RULE-07` show a `Quy tắc gốc` badge.
- Seeded rules can be edited and toggled on or off, but they never show a delete control.
- Admin-created rules show a `Theo dõi` or equivalent metadata-only badge and supporting helper text: `Quy tắc này chỉ lưu metadata, chưa tự động áp dụng vào pipeline.`
- Create and edit form fields:
  - Tên quy tắc
  - Mô tả
  - Danh mục
  - Trạng thái hoạt động
- Primary form submit label uses `Lưu cấu hình`.
- Soft delete is allowed only for non-seeded rules and must always go through an alert dialog confirmation.
- Destructive action styling uses the destructive color only for the delete or disable trigger and the confirmation dialog emphasis.

### 4. Template mapping management contract
- Route is `/admin/templates`.
- Primary surface is a table inside a card container.
- Table columns, in this order: `Loại tour`, `Loại đầu ra`, `Canva Template ID`, `Trạng thái`.
- Clicking a row opens a right-side edit sheet on desktop and a full-width sheet on mobile.
- The edit sheet layout order:
  1. Template ID input
  2. Active status toggle
  3. Read-only explanation of field mapping purpose
  4. Two-column mapping grid
- Two-column mapping grid rules:
  - Left column label: `Trường dữ liệu`
  - Right column label: `Tên text element trong Canva`
  - Left column is read-only and derived from structured draft schema.
  - Right column is editable by admin.
- Do not allow inline editing directly inside the table.
- Save flow is synchronous from the user perspective:
  1. User clicks `Lưu cấu hình`.
  2. Inputs disable immediately.
  3. Inline progress text appears: `Đang xác minh mẫu Canva...`
  4. System verifies template accessibility before persisting.
  5. Success shows confirmation toast `Đã lưu cấu hình.` and closes or refreshes the sheet.
  6. Failure keeps the sheet open and renders the defined destructive error state copy inline.
- Invalid template verification must never silently fall back or save partial data.
- Active or inactive status must be visible both in the table and inside the edit sheet.

### 5. Interaction and accessibility rules shared across this phase
- Every interactive control must have a visible focus ring using the accent color.
- Minimum hit target is 44px for toggle controls, pagination buttons, and explicit action buttons.
- Never communicate system state by color alone. Status text is mandatory.
- Destructive actions always require confirmation before persisting the change.
- Use sentence-style Vietnamese labels, not icon-only controls, for critical actions in admin screens.
- Keep this phase visually lightweight. The goal is quick retrieval and safe configuration, not dense operations dashboards.
